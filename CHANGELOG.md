# Changelog
## 3.0.0 (Aurora After Dark), from 2.4.3
**Development branch only. Production/main is still 2.4.3.**
- Major visual redesign across both student and teacher interfaces using the animated Aurora After Dark starfield and aurora background.
- Student booking is optimized for release-time rushes: compact calendar, live opening count, one-tap **Next open**, stronger open-day emphasis, open-only lists by default, unavailable/taken times hidden behind an optional reveal, and a schedule-driven period filter that also controls Calendar, Times, Next open and race-recovery suggestions.
- Student names can be remembered for the current browser session to speed up retries; assignment titles are never saved and always start blank. If a slot is taken during the click race, the losing student is immediately offered up to three current alternatives.
- Teacher Overview now has **Rush Mode** with live open / held / booked totals and a net-booking delta.
- Teacher Settings now has **teacher-managed full-site themes**: Aurora After Dark (default), Fall, Halloween and Winter. Aurora alone keeps the northern-lights/starfield identity. Fall is a separate harvest world with animated falling leaves, branches/acorns, sunset atmosphere and warm paper/leather controls; Halloween has its own moon, fog, bats, pumpkins, candy, graveyard/skeleton details and haunted controls; Winter has falling snow, festive lights, pines, gifts, snowbanks and frosted controls. Calendar cells, cards, navigation, buttons, forms, dialogs, student panels, teacher dashboards and Lockdown inherit the selected world. The selected appearance updates live through the existing settings Realtime signal. Migration `004_v300_themes.sql` is required; booking rules are unchanged.
- Teacher Schedule now has **Publish & open day**: drafts are published first, then the existing protected bulk-open function opens safe slots while paper-taken, booked, past, and other protected states remain untouched.
- Phone portrait and landscape behavior was rebuilt, especially short landscape screens; sheets/dialogs, navigation, calendars, forms and teacher workspaces now have explicit rotation-aware rules.
- New TEST-only `npm run test:stress` can race up to 200 separate student sessions for one disposable open test slot. It deliberately tests holds only and does not create a booking.
- Added `DEVICE_TEST_V3.md` for real iPhone/Android/tablet/Chromebook/Mac portrait, landscape and rotation verification.
- No production deployment was performed as part of v3 development.

## 2.4.2 (verification-script correction), from 2.4.1
**No new features. No frontend behaviour change (only the version and the What's New entry). Migration 003 changed by ONE guard. Migrations 001 and 002 are untouched.**
**Still NOT executed against any PostgreSQL or Supabase database: none was available. Everything below is static analysis, libxml2 checks of the XPath, and unit tests.**
- **`verify_v240_READONLY.sql`, XML extraction (the defect you reported):** the five `/row/c/text()` expressions (checks 70, 71, 72 twice, 73) are gone. Precisely: the script called `query_to_xml(..., false, true, '')`, i.e. `tableforest = true`, which gives a bare `<row>` for one row, so the old path matched only that case and nothing in the `<table><row><c>` document most people expect. With `tableforest = true`, zero rows give an EMPTY value and several rows give a multi-root fragment, and `xpath()` needs a single-root document, so those cases would have raised an error and aborted the whole report instead of reporting a FAIL. Now: `tableforest = false` (always one `<table>` document), path `/table/row/c/text() | /row/c/text()` (also accepts the bare row), each probe runs ONCE (check 72 used to run its query twice), and a probe with no value is a **FAIL that shows the start of the raw XML**, never a silent `?`. The path was validated with libxml2 (`xmllint`) against hand-written XML in each documented shape. PostgreSQL itself did not produce that XML.
- **`verify_v240_READONLY.sql`, transaction claim:** `SET TRANSACTION READ ONLY` does not guarantee safety. It only works inside a transaction block; if an editor sends statements one at a time, PostgreSQL ignores it with a warning (25P01) and the SELECT runs unprotected. It was never confirmed how the Supabase SQL Editor submits a script. The script is now ONE statement (no `SET`, no `BEGIN`, no second statement, no semicolon except the last character), so it does not depend on the editor. It is read-only because its text contains no write statement (unit-tested), and a new row "transaction mode of this run" says whether PostgreSQL also enforced it. An optional `psql ... BEGIN READ ONLY` recipe is in the file header (not executed).
- **`verify_v240_READONLY.sql`, smaller:** `?&` replaced by counting `jsonb_object_keys` (some clients treat `?` as a parameter marker); check 72 now says whether the roster switch is on, because with the switch off it only proves the switch; two inherited semicolons (one comment, one string) removed; new check 64 (WARN level): can the role that owns `rt_notify` insert into `realtime.messages`? (a swallowed failure would otherwise show only as "no live updates").
- **Migration 003 (one change):** a guard that refuses to run, before changing anything, when row level security is OFF on `realtime.messages` (the receive policies would not be enforced; the verify script already treats that as a FAIL). Everything else was re-audited and left as it was; see AUDIT.md "v2.4.2".
- **Tests:** 7 new or replaced static tests (one statement, no `SET`, no stray semicolon, honest transaction wording, probe shape, no silent `?`, check 64, docs), 2 libxml2 XML tests (skipped automatically if `xmllint` is missing), 2 migration tests. Version tests now expect 2.4.2.
- **Docs:** AUDIT, TESTING, SETUP, README, REALTIME, PRIVACY updated.

- **Readable activity timeline** for new and legacy events (`admin_activity`, structured `meta` on new events).
- **Version label** (student footer, teacher sidebar), About Aurora and What's New in Settings. Version injected from package.json at build time.

## 2.3.0 (AURORA Evolution), from 2.2.0
**Imported-appointment investigation (no database change, no migration):**
- Verdict: editing an imported slot behaves as designed. `admin_upsert_slot` changes only date, period, time and room, so a slot that came from the paper sheets stays *unavailable*; the student calendar shows unavailable slots as "closed", and `list_slots` hides every slot whose start time has passed (by now almost the whole imported sheet is in the past). New slots default to *available*, which is why they appear and imported ones do not. The server rules are untouched.
- Real defects found in the teacher screen and fixed there: "Done." hid the real outcome; "Make available" on a past slot looked successful but could never be booked; the default date range (UTC "today" minus 14 days) hid imported Sept 28-29; "today" came from the UTC clock (wrong after 8 pm New York time); re-closing a paper slot silently replaced "Taken on paper" with "Not available"; the old table had no search, filters, period grouping or Past/Paper indicators; period could not be edited although the server supports it.
- Added: status model (Open, Unavailable, Taken on paper, Booked online, Held, Draft, plus Past), filters with counts, search, per-slot explanation, live "if you save" preview, saved-outcome messages, confirmation before opening a paper slot, Open disabled for past slots with the reason, a reason choice when closing, a default range that covers all imported dates, school-time-zone dates.
**Redesign:** new information architecture for student and teacher (rail + workspace + contextual panel on desktop; top bar + bottom tabs + sheets on phones), original logo and ribbon motif, redesigned booking flow with hold ring, inline validation, expired-hold recovery and a success ticket with an .ics download, teacher command center (Overview with KPIs and composition bar, Schedule master-detail, Bookings master-detail with a real edit form instead of prompts, Settings, a dedicated Lockdown screen), toasts and in-page confirmations replacing `alert/confirm/prompt`, motion system, safe-area and landscape support, keyboard arrows in the calendar.
**Code:** the single 9 KB App and Admin files became about 30 focused modules plus four stylesheets; `App.jsx` and `Admin.jsx` remain the orchestration layer.
**Tests:** 25 new unit tests (85 total; the original 60 are unchanged), a rewritten browser harness (89 checks incl. all old live-update assertions ported), 7 new static checks. See TESTING.md for what was and was not run.
**Unchanged on purpose:** backend, SQL, seed, RLS, function-only access, holds, booking rules, Lockdown, polling intervals (5 s teacher, 15 s student), dependencies (none added), GitHub Pages workflow.
